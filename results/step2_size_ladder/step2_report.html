Branch B · Step 2 — Model-size ladder

Is trajectory accuracy cheap — does a smaller DA3 do the job?

Fixed resolution 504, five sizes small → base → large → giant → nested-giant, 3 repeats on the same frozen keyframes as Step 1. The hypothesis (H2) was that ATE saturates well below the biggest model. It does not.

The finding in one line

Model-size reduction is not a free lever. On both indoor datasets only the nested-giant architecture reaches good ATE — the plain small→giant ladder is flat and ~3× worse — so it is "nested vs not", not "bigger vs smaller". H2 is false.

Synthesis & caveats

  • H2 is false. Trajectory ATE does not saturate below the largest model — it steps sharply at the nested-giant architecture on both indoor datasets, and only softens (giant≈nested) on UAS. There is no smaller size that Pareto-dominates for localization.
  • The dissociation the plan hoped to show isn't there. Map point count is size-invariant (depth is dense at every size), so density is not a size lever. Chamfer-to-nested tracks ATE because the clouds are pose-projected — on the size axis it measures trajectory error, not independent map quality, so we don't over-claim a trajectory-vs-map gap.
  • Combined with Step 1: neither static knob — resolution nor size — yields a generalizable Pareto win. Both point the same way: the real speedup has to come from temporal reuse, not from shrinking the model.
  • Caveats. Single server GPU (RTX 3090-class); no Jetson, so latency/memory are server-only. Repeat band ~10⁻⁵–10⁻³ m (bf16), below every gap. UAS map-detail omitted; campus_fog is a held-out platform (UniPilot handheld).
